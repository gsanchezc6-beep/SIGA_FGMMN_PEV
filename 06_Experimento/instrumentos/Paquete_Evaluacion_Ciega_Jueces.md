# Paquete de evaluación ciega — Comparación de calidad de RF

Proyecto SIGA — Componente empírico, Enfoque 1

Instrucciones: puntúe cada ítem de 1 a 5 en las 5 dimensiones de la rúbrica adjunta (`rubrica_evaluacion.md`), de forma independiente, sin consultar a otras personas evaluadoras. No se indica el origen de cada ítem: unos provienen del equipo de desarrollo, otros de un modelo de lenguaje; el orden fue aleatorizado.

---

**Item-01.** El sistema debe permitir el monitoreo y ajuste remoto de la climatización del aula.

**Item-02.** El sistema debe detectar automáticamente si un aula está ocupada o vacía mediante sensores de presencia.

**Item-03.** El sistema debe apagar automáticamente los equipos de un aula cuando esta quede desocupada.

**Item-04.** El sistema debe permitir consultar el historial de un ticket de mantenimiento mostrando el estado actual, la fecha y hora de cada actualización, sin duplicar columnas de estado anterior/nuevo.

**Item-05.** El sistema debe indicar si los sensores y dispositivos IoT de un aula están conectados y transmitiendo datos correctamente.

**Item-06.** El sistema debe permitir programar horarios automatizados de encendido y apagado de equipos.

**Item-07.** El sistema debe analizar el comportamiento histórico de los equipos para estimar la probabilidad de fallas futuras mediante Inteligencia Artificial.

**Item-08.** El sistema debe permitir el monitoreo y control remoto de los proyectores del aula.

**Item-09.** El sistema debe registrar en una bitácora las acciones relevantes ejecutadas por los usuarios del sistema.

**Item-10.** El sistema debe registrar y mostrar en tiempo real la temperatura y el estado de ocupación de cada aula.

**Item-11.** El sistema debe notificar de forma inmediata al personal técnico cuando una falla afecte una clase en curso o comprometa equipos esenciales.

**Item-12.** El sistema debe controlar automáticamente el apagado energético de equipos según reglas configuradas.

**Item-13.** El usuario autorizado debe poder visualizar y enviar comandos (encender/apagar/ajustar) a los dispositivos de un aula sin desplazarse físicamente.

**Item-14.** El sistema debe generar reportes estadísticos periódicos sobre el uso y estado de las aulas.

**Item-15.** El sistema debe notificar de inmediato al usuario que reportó una falla que su solicitud fue recibida por el responsable, dentro del horario laboral.

**Item-16.** El sistema debe permitir registrar, al inicio y al final de cada sesión de clase, el estado de los equipos del aula (proyector, climatización), dejando constancia de en qué condición se recibió y se dejó el espacio.

**Item-17.** El sistema debe notificar simultáneamente a la autoridad de la facultad, a la persona que reportó el incidente y al responsable de la reparación cuando se registre una incidencia.

**Item-18.** El sistema debe generar reportes con el porcentaje de ocupación promedio, el consumo eléctrico estimado y las incidencias registradas de un aula en un periodo determinado.

**Item-19.** El sistema debe monitorear la conectividad de red de los dispositivos IoT instalados en las aulas.

**Item-20.** El sistema debe ofrecer un catálogo de tipos de incidencia que incluya, además de fallas de equipo, categorías como mobiliario deteriorado, pizarra en mal estado, problemas de iluminación, inundación del aula y aula cerrada.

**Item-21.** El sistema debe apagar automáticamente el aire acondicionado cuando detecte que un aula quedó desocupada.

**Item-22.** El sistema debe exponer, también al rol docente, el historial de intervenciones de mantenimiento realizadas sobre un equipo específico.

**Item-23.** El sistema debe permitir registrar una solicitud de mantenimiento indicando aula, equipo afectado, tipo de incidencia y una fotografía opcional del problema.

**Item-24.** El sistema debe permitir a la persona usuaria exportar sus propios datos personales almacenados, conforme al derecho de acceso.

**Item-25.** El sistema debe permitir ajustar remotamente la temperatura del aire acondicionado del aula.

**Item-26.** El sistema debe advertir a los usuarios cuando la conectividad de red del aula no permita el funcionamiento normal del sistema, dado que no todas las aulas cuentan con acceso a internet.

**Item-27.** El sistema debe generar y enviar alertas automáticas cuando detecte anomalías técnicas o condiciones fuera de los parámetros configurados.

**Item-28.** El sistema debe ser consultable desde un teléfono celular, sin requerir instalación adicional.

**Item-29.** El sistema debe permitir gestionar solicitudes de mantenimiento, desde su registro hasta su cierre.

**Item-30.** El sistema debe filtrar la vista de aulas del rol docente, mostrando únicamente las aulas correspondientes a su horario de clases.

**Item-31.** El sistema debe generar una alerta automática cuando detecte una anomalía en el funcionamiento de un equipo del aula (proyector, climatización).

**Item-32.** El sistema debe permitir verificar y, cuando el hardware lo soporte, controlar remotamente el estado de encendido de los proyectores del aula.

**Item-33.** El sistema debe capturar en tiempo real temperatura, humedad y ocupación de cada aula mediante sensores IoT distribuidos.

**Item-34.** El sistema debe presentar un panel de control centralizado con la información consolidada de sensores, proyectores, climatización y conectividad.

**Item-35.** El sistema debe registrar el historial de ocupación de cada aula incluyendo fecha, hora de inicio, fin, duración y estado detectado.

**Item-36.** El sistema debe permitir exportar reportes administrativos en formato PDF y Excel.

**Item-37.** El sistema debe registrar en una bitácora las acciones relevantes ejecutadas por los usuarios (control remoto de equipos, gestión de roles).

**Item-38.** El sistema debe enviar notificaciones automáticas cuando detecte proyectores o equipos de climatización encendidos fuera del horario académico vigente.

**Item-39.** El sistema debe permitir el acceso diferenciado por roles, habilitando únicamente las funciones autorizadas según el perfil del usuario.

**Item-40.** El sistema debe permitir clasificar cada alerta según su nivel de prioridad (por ejemplo, baja para un goteo de aire acondicionado, alta para una inundación del aula).

**Item-41.** El sistema debe presentar al personal no técnico una vista simple del estado de las aulas, comprensible sin explicación previa.

**Item-42.** El sistema debe mostrar la cantidad de equipos de cómputo en buen estado disponibles en un laboratorio, considerando la capacidad requerida según la asignatura.

**Item-43.** El sistema debe integrarse con el sistema de videovigilancia existente para consulta agregada de estado.

**Item-44.** El sistema debe analizar patrones de consumo energético de los equipos del aula.

**Item-45.** El sistema debe explicitar y aplicar permisos distintos según el rol del usuario (por ejemplo, si un docente puede reportar o solo consultar alertas).

**Item-46.** El sistema no debe permitir que el personal docente visualice el contenido de las cámaras de videovigilancia de las aulas.

**Item-47.** El sistema debe consultar, de forma agregada y sin identificar personas, si las cámaras de videovigilancia de un aula están operativas.

**Item-48.** El sistema debe permitir consultar qué aulas están libres u ocupadas en un momento dado, sin necesidad de desplazarse físicamente.

**Item-49.** El sistema debe registrar cada falla y mantenimiento con fecha, hora, tipo de incidente, aula, equipo afectado y responsable.

**Item-50.** El sistema debe permitir consultar qué aulas están disponibles cuando la asignada resulta inutilizable, para facilitar un cambio de espacio.

**Item-51.** El sistema debe permitir a la persona usuaria solicitar la rectificación de sus datos personales almacenados.
